# 事前登録 — 決算発表タイミング（EARNINGS_TIMING）

作成: 2026-08-04（**リターンを一切見ていない時点で確定**）
ファミリー: `EARNINGS_TIMING`（新規）

## 0. 既存のPEAD棄却とどこが違うか

RESEARCH_SUMMARY の棄却リストにある **PEAD は「発表**後**のドリフト」**。
本仮説は**発表**前**のタイミング**を使うもので、必要なデータも情報源も別。

また AGENTS の「決算日除外は逆効果（ギャップはアルファ源）」は
**決算日を避ける**話であり、**決算日を狙う**本仮説とは反対方向。

★**構造上の狙い**: 直近7例が死んだ壁は「αがショート側にあり、その銘柄が借りられない」。
本仮説は**αをロング側に置き、ショートは流動ユニバース全体の市場バスケット**にする。
ショート銘柄はαを担わないので、貸借制約が効いても崩れない設計。

## 1. データとPIT

- **`/v2/equities/earnings-calendar`（決算発表予定日）は当日分79件しか返さず、
  パラメータを全て無視する**（date/from/to/code いずれも効かない）。
  **履歴が無いのでバックテストには使えない**。今日以降の蓄積用途に限る。
- したがって予定日は **`fins` の実績発表日 `DiscDate` から自前で構成**する。
  手元 `fins`: 2021-04-19〜2026-04-24・65,849行・2,881銘柄。`DocType` で 1Q/2Q/3Q/FY を識別。

**予想発表日（PIT安全）**: 銘柄 s・四半期 q について
`expected(s,q,y) = DiscDate(s,q,y-1) + 364日` を営業日に丸めた日。
前年の実績だけで決まるので、当年の情報を一切含まない。前年同期の実績が無い銘柄は対象外。

## 2. 主仕様 A — 発表前ドリフト（確定）

- 毎営業日、**予想発表日まで1〜5営業日**の銘柄を「発表前バスケット」とする
- そのバスケットを**等加重ロング**
- 同額を**流動ユニバース（前日売買代金≥¥10億・貸借銘柄）の等加重**で**ショート**＝市場中立
- 日次リターン = バスケット − 市場バスケット
- **実際に発表された時点でその銘柄は即日除外**（発表後は保有しない＝PEADと混ざらない）
- コストは**実現ターンオーバー × 1.0bps/side**（板寄せ実測。両サイドに課金）
- 建玉が5銘柄未満の日は不参加（薄すぎる日を無理に建てない）

## 3. 副仕様 B — 発表遅延（同時に1回だけ測る）

予想発表日を **3営業日以上過ぎても未発表**の銘柄を**ショート**、市場を**ロング**。
「遅れる決算は悪い知らせ」という定型事実の検証。
**ショート側は貸借銘柄かつ規制なしに限定**（借株制約を最初から入れる）。

## 4. 窓（確定）

- **選択窓: 2022-01-01〜2024-12-31**（前年実績が要るので2022年開始）
- **確認窓: 2025-01-01以降** ← **選択窓で基準を満たした場合のみ、1回だけ開く**

選択窓で落ちたら確認窓は消費しない。

## 5. 判定（実測を見る前に確定）

主仕様Aが選択窓で次を**両方**満たしたときのみ確認窓へ進む:

1. コスト後 **net Sharpe ≥ 1.0**
2. 年別（2022/2023/2024）で**負の年が1年以下**

確認窓でも同じ基準を適用し、満たさなければ棄却。

副次（判定に使わない）: 建玉数の推移、実現ターンオーバー、グロス、B仕様の結果。

## 6. 禁止事項

- 結果を見た後の窓幅（1〜5営業日）・閾値・コスト・ユニバースの変更
- 副仕様Bが良かった場合にBを主仕様へ昇格させること
- 選択窓で落ちたのに確認窓を開くこと
- 発表後のリターンを混ぜること（PEADは既に棄却済みの別ファミリー）
