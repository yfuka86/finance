# 長期・高信頼データソース開拓 — 2026-08-01

## 選定基準

本メモでは、次をすべて満たすものだけを「採用候補」とする。

1. 一次提供者（取引所・官公庁・中央銀行）または一次データの正式再配布者
2. 原則10年以上、例外なく複数景気循環を含む履歴を取得可能
3. 観測日・公表日・訂正を区別でき、PITデータセットを構築できる
4. 個人研究で合法的・継続的に取得できる経路がある
5. 既存の J-Quants Premium / Stooq / `data/jp_flows` と実質重複しない

HTMLスクレイピングは個人利用でもサイト規約を上書きしない。公式APIまたは公式バルクを優先し、
HTMLだけのサイトは規約、robots、レート制限を確認してから低頻度・差分取得する。

## 結論

すぐ着手する価値がある新規ソースは、次の3本。

| 優先 | データ | 公式履歴 | 費用 | 主な用途 | 判定 |
|---:|---|---:|---:|---|---|
| 1 | 特許庁 特許情報バルク | 電子公報1993年～ | 無料（媒体等実費） | 技術投資、特許公開・登録・失効イベント | **GO** |
| 2 | 日本銀行 時系列統計API | 系列ごとの全長期履歴 | 無料 | 金融条件、貸出、資金循環、業種別活動のレジーム | **GO** |
| 3 | e-Stat 統計API | 統計ごとに10年以上 | 無料 | 業種需要、在庫、設備投資、地域需要 | **条件付きGO** |

JPXの企業行動、TDnet、オプション板は品質は最上位だが、個人が取得できる長期商品または十分な
長さを満たさず、現時点では採用しない。気象・人口など、企業や取引フローへの結合が弱い一般的な
代替データは、履歴が長くても対象外とする。

## 1. 特許庁 特許情報標準データ / 公報バルク

- 正本: 特許庁・INPITの一括ダウンロードサービス。
- 完全性検証用のJPオーソリティファイルは1993年以降の電子公報を収録する。
- 書誌・経過情報はTSVで、原則翌開庁日に更新。過去分は外部媒体コピーで取得可能。
- 利用料は無料。過去媒体・送料・保存領域は利用者負担。
- 使えるPIT時刻は、出願日ではなく**公開日／公報発行日／登録公報日／処分公示日**。
  出願日は公開前に市場参加者が知らないため、特徴量の有効日には使わない。

モデル候補:

- 上場会社別の公開特許件数、被引用・共同出願、技術分類の新規性
- 登録査定、拒絶、権利消滅、譲渡のイベント
- 企業の技術ポートフォリオと業種平均との差、競合企業の出願急増
- CORPORATE_EVENTS の独立イベント系列。ただし現在の4研究枠を増やさず、同ファミリー内の
  将来候補として保管する

主なリスク:

- 出願人名から証券コードへのPIT名寄せが最大の工数。現社名への遡及置換は禁止する。
- 子会社・大学・共同出願の帰属を別列で保持する。
- 件数だけでは規模因子になるため、業種・研究開発費・時価総額で正規化する。

最小収集仕様:

`data/jp_patents/raw/{release_date}/` に原本を不変保存し、SHA-256、取得時刻、提供ファイル名を
manifestへ記録する。派生表は `(publication_id, version_received_at)` を主キーにし、訂正を上書き
しない。最初は2010年以降でパーサと名寄せを検証し、通過後に1993年まで広げる。

## 2. 日本銀行 時系列統計API

- 2026年2月に公式APIが開始。JSON/CSVを取得でき、コード、階層、メタデータの3 APIがある。
- 日銀は約20万系列の長期時系列を提供する。
- データは季節調整、基準改定、速報改定等で遡及改定されることが明記されている。

モデル候補:

- 貸出約定平均金利、銀行貸出、マネーストック、CP・社債、企業金融判断
- 資金循環、海外投資家フロー、為替、物価、短観の公表サプライズ
- 個別株へ直接投入せず、金融・不動産・輸出・内需セクターのレジーム交互作用に限定する

PIT上の注意:

- APIの現行値だけを過去へ並べると、速報改定や季調改定の先読みになる。
- 初回取得値を履歴PITと主張しない。過去バックテストでは、公表資料のヴィンテージが復元できる
  系列だけを使うか、改定されにくい市場日次系列に限定する。
- 今後は日次append-onlyでレスポンス、取得時刻、系列メタデータを保存する。

最小収集仕様:

まずメタデータを全取得し、`frequency`, `unit`, `seasonal_adjustment`, `start_date`, `last_updated`
をカタログ化する。候補系列は事前に20本以下へ固定し、毎日差分取得する。値の上書きは禁止し、
`(series_code, observation_period, received_at)` で保存する。

## 3. e-Stat / 統計ダッシュボードAPI

- 官公庁統計の公式API。統計ダッシュボード側は登録不要で約6,000系列、XML/JSON/CSVに対応。
- 法人企業統計、鉱工業指数、商業動態、機械受注などを統一的に探索できる。
- 履歴長は統計ごとに異なるため、**メタデータ上で10年以上を確認した系列だけ採用**する。

モデル候補:

- 業種別売上・在庫・設備投資の水準と公表サプライズ
- 企業イベントモデルの事前需要環境、TOPIX2026候補群の業種レジーム

PIT上の注意:

- 政府統計も改定・基準改定・季調替えがある。現行時系列はヴィンテージではない。
- 公開（更新）日を保存し、今後のフォワード特徴量を作る。過去評価は公表資料のアーカイブで
  初回値を復元できる統計に限る。
- 月次・四半期データを日付へ展開するときは、対象月末ではなく実際の公開日時から有効化する。

## 品質は高いが今回の条件で不採用

### TDnet個人向けアドオン

月額11,000円でAPI・CSV、過去5年。正確性とPIT時刻は良いが10年基準を満たさない。
BUYBACK_PRESSURE / CORPORATE_EVENTS のフォワード収集には有用だが、長期バックテストの正本には
しない。過去5年を買っても「長期データを取得できた」と扱わない。

### EDINET API

法定開示、提出日時、XBRLという点で高品質だが、書類種別ごとに法定縦覧期間があり、APIだけで
2008年以降の全イベントを一括復元できるとは限らない。現行APIは**今後のappend-onlyイベント収集**
には採用できるが、長期イベントバックテストの単独正本にはしない。J-Quantsの既存財務データと
重なる財務諸表数値の再収集もしない。

### JPX Corporate Action / J-Quants Pro

JPXの企業行動データは全上場会社を標準化したgolden sourceで、Pro版は10年以上を明記する。
しかしProは法人向けで、個人利用の取得経路ではない。通常の企業行動Webサービスも月額9万円以上
（区分による）で、個人契約可否が明確でない。個人向けDataCubeで同等の企業行動履歴が購入可能と
確認できるまで保留する。

### JPXデリバティブ板 / J-GATE

J-GATEの全注文情報は2016年以降（CSV）、2019年以降（Order/Trade）、2021年以降（現行ITCH）で、
OTM_SKEW_VERTICALの実スプレッド・複数レッグ約定検証に最も正確。ただし全注文情報は10年未満で、
Spotは最低5営業日、日額課金＋処理費。通常のDataCubeオプションtick/OHLCは約定データであり、
historical bid/askを保証しない。現在の「長期のみ」条件では購入しない。

### TOPIX構成銘柄履歴

JPXはDataCubeの月末指数マスタを正規経路として案内する。TOPIX自体は1969年開始だが、構成銘柄の
個人向け商品について取得可能期間・費用を公開ページだけで確定できない。TOPIX2026フォワードには
現行公式ファイルを使い、過去構成を推測・再構築して長期履歴と称しない。

### 詳細売買内訳・証券金融データ

JPXの詳細売買内訳は2010年以降のProデータがあるが法人向けで月額37.5万円（2026年4月以降）。
個人向けPremiumで既に収集済みの売買内訳と重複するため新規購入しない。S&P/JPXの貸株統合データも
長期資料は5年以上の表記に留まり、10年基準を満たす確認ができない。

## 実行順序

1. 特許庁バルクの利用登録と、2010年以降の過去分媒体サイズ・提供手順を問い合わせる。
2. BOJ APIメタデータを取得して、10年以上・改定属性・公表頻度で機械フィルタする。
3. e-Statで同じカタログを作り、既存特徴量と重複しない系列だけ残す。
4. 上の3本は直ちに仮説評価へ入れず、まず原本、PIT時刻、訂正履歴、カバレッジを監査する。
5. 4研究枠は増やさない。特許はCORPORATE_EVENTS、BOJ/e-Statは既存各ファミリーの説明変数候補として
   登録し、未使用期間を定めてから1回だけ評価する。

# 追記 2026-08-04 — FX データソース（実地検証済み）

FX を新規アセットとして検討するにあたり、実際にアクセスして確認した結果。

## 結論

| 用途 | 採用 | 状態 |
|---|---|---|
| 約定可能な bid/ask 価格 | **Dukascopy datafeed** | **GO**（無料・キー不要・ECN実クオート） |
| 日次仲値の長期系列 | **ECB 参照レート** | GO（1999-01-04〜・公式・無料） |
| 政策金利（キャリー近似） | FRED CSV | 条件付き（月次・CHFは2024-03、NZDは2024-12で停止） |
| **実スワップポイント履歴** | **無し** | **恒久的な穴。お金では解決しない** |

## Dukascopy datafeed（検証済み・2026-08-04）

キー不要。`MM` は **0起点**（00=1月）。LZMA(FORMAT_ALONE)圧縮、1レコード24B、
`>iiiiif` = (期間先頭からの秒, 始値, 終値, 安値, 高値, 出来高)。価格は整数スケール
（JPY建て×1000、その他×100000）。

| 粒度 | パス | レコード | サイズ |
|---|---|---:|---:|
| ティック | `{PAIR}/{Y}/{M}/{D}/{H}h_ticks.bi5` | 可変 | 8-20KB/時 |
| 1分足 | `{PAIR}/{Y}/{M}/{D}/BID_candles_min_1.bi5` | 1440/日 | 約12KB |
| **1時間足** | `{PAIR}/{Y}/{M}/BID_candles_hour_1.bi5` | 720/月 | 約6.6KB |
| 日足 | `{PAIR}/{Y}/BID_candles_day_1.bi5` | 365/年 | 約4.5KB |

`ASK_` 版も同じ形で存在するので**スプレッドが実測できる**。
連続取得すると接続を切られるので 0.25 秒程度の間隔が要る。
**USD絡み7ペアだけで8通貨の強弱行列が復元できる**（クロスは差）ので28ペアを落とす必要はない。

## ★実スワップポイント履歴が取れないのは構造的な問題

- GMO/DMM 等の**スワップ履歴を返すAPIは存在しない**（公表ページもJS/ログイン配下）。
- 第三者ベンダーのフォワードポイントを買っても、**スワップはブローカー固有**なので
  「自分が実際に受け取れたはずの額」にはならない。**有料化で解決しない**。
- したがって FX の研究は2つに割れる:
  - **数日以内で完結** … スワップの影響が小さく Dukascopy だけで検証可能
  - **数週間以上／キャリー** … スワップが一次項目。政策金利での近似は **PAPER ONLY** 相当

## スワップの曜日規約（GMO FXネオで確認・2026-08-04）

`trading/fx/swap.py` に実装（退行テスト `tests/test_fx_swap.py`）。

- 付与は **NYクローズ**（JST 07:00、米夏時間は 06:00）
- **水曜のNYクローズを跨ぐと3日分**（T+2の受渡日が金→月へ飛ぶため）。付与は木曜07:00
- 土日はロールオーバー無し。祝日でロールオーバーしない日もある
- **週合計 1+1+3+1+1 = 7 日**（ここが合わないと規約の解釈が誤り＝テストで固定）
- ブローカーは金利差をそのまま渡さない。`passthrough`（渡す割合）と `haircut_bp`
  （受払いどちらでも自分の不利に働く年率bp）を明示パラメータにした。
  **これは公表値に合わせて較正するもので、成績を合わせるために動かしてはいけない。**

## 税区分

FX（店頭）は**申告分離課税20.315%＝先物・オプションと同じ枠**。
日経225オプションのカレンダーと損益通算できる。**株式とは通算できない**。
