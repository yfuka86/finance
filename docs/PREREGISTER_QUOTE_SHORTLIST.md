# 事前登録 — 気配取得を短縮する候補プリスクリーン（QUOTE_SHORTLIST）

作成: 2026-08-03（**結果を見ていない時点で確定**）
ファミリー: `QUOTE_SHORTLIST`（新規）

## 0. なぜ今これを試すのか

`ensemble_core` は同じ借株制約の下で **単元OOS24+ Sharpe 3.43**（`verify_baseline.py` 4/4 PASS で
再現確認済み）。直近6例を殺した借株の壁には当たっていない。死んでいる理由は**気配の取得経路だけ**。

そこに2つの未解決の記述がある:

1. AGENTS「**ユニバースを削って高速化できるか → 動作点が無い**」
   … ただしこれは**流動性フロアで削った場合**の検証。**シグナルで絞る場合は未検証**。
2. AGENTS「**『気配が寄値を予測しない』という実測は66秒スメアと分離できていない**。
   kabuでの再測定は無意味（同じスメアが乗る）」

kabu の実測スループットは ~9.5銘柄/秒。467銘柄で49-66秒＝銘柄ごとに最大1分の観測時刻ずれ。
**候補を50銘柄に絞れば約5秒**で、必要スペック（467銘柄≤5秒＝95銘柄/秒）と同等の同時性が
kabu のままで得られる。スメアは12分の1。

つまり本仮説が通れば、**ユーザーの実弾NO-GO判定（建玉一致率<50%）の前提が変わる**。
通らなければ、気配経路は throughput 側からも閉じたと確定できる。

## 1. 検証すること（シミュレーションのみ・新規データ不要）

**前日確定データだけで作った候補リスト K 銘柄に最終選択を限定したとき、
`ensemble_core` の成績がどれだけ残るか。**

- プリスクリーン指標: **`gap_vol60`**（その銘柄自身の残差ギャップの60日ボラ・PIT・shift済み）。
  大きなギャップが出る銘柄を前日までに当てる、という素直な指標。気配を一切使わない。
- 各営業日、`gap_vol60` 上位 K 銘柄だけを残したパネルで `ensemble_core` を実行する。
- **K = 30 / 50 / 100 / 200 / 全銘柄（対照）**
- 執行・制約は本番同等（¥20M・8銘柄/側/スリーブ・信用2.0倍・¥10億フロア・貸借のみ・
  規制銘柄ショート除外・100株単元・寄成→引成）。コストは 7bps/side（`verify_baseline` の
  環境再現アンカーと揃える）。評価は **OOS24+**。

## 2. 合格基準（実測を見る前に確定）

**K = 50**（≒5秒で取得できる規模）において次を**両方**満たしたときのみ次段階へ:

1. 単元OOS24+ **Sharpe ≥ 1.0**（リポジトリ共通基準）
2. 全銘柄版に対する **Sharpe 維持率 ≥ 50%**

副次（判定に使わない）: K=30/100/200 の維持率カーブ、年率、DD、実際に建った銘柄数。

## 3. これが通った場合に必要なこと（今回はやらない）

本試行は**シミュレーション上の可否**だけを見る。通っても実弾GOではない。
順序は: ①K=50でのSharpe維持を確認 → ②50銘柄の気配スナップショットを実測して
`analyze_quotesnap.py --book` で建玉一致率を出す → ③既存の対応表
（≥75%→GO / 50-75%→減額 / <50%→NO-GO）に当てる → ④ユーザー承認。

## 4. 禁止事項

- 結果を見た後のプリスクリーン指標・K・コスト・評価窓の変更
- K=30/100/200 のうち良かったものを主仕様（K=50）に昇格させること
- 本結果を「気配問題が解決した」と読むこと（解決するのは**同時性**だけ。
  気配そのものの予測力は別途実測が要る）
