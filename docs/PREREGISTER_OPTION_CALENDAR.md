# 事前登録 — 日経225オプション カレンダースプレッド（OPTION_CALENDAR）

作成: 2026-08-03（**結果を見ていない時点で確定**）
ファミリー: `OPTIONS`（先物・オプションだけで損益が完結する独立戦略枠）

## 0. なぜこの構成か

同枠で2本すでに落ちている。その死因を構造的に避ける形を選ぶ:

| 既存 | 死因 |
|---|---|
| ATMストラドル IV−RV | **裸売りの無限損失**。2025-03-31の1回でpremium比 −144%、DD−144% |
| OTMスキュー縦スプレッド | 清算値段階で全年度マイナス（Sh−0.66）。同一限月のスキューには構造が無かった |

カレンダーは **同一ストライクで期近を売り・期先を買う** ネットデビット構成なので、
**最大損失が支払デビットに限定される**（裸売りの死因を機構的に排除）。
また使うのは IV の**水準**でも**同一限月のスキュー**でもなく、**期間構造の傾き**で、
既存2本とは別の情報源。RESEARCH_SUMMARY が次の候補として明示していたもの。

## 1. データ

`data/jp_options/opt225_*.parquet`（2019-01〜2026-07・1,389,620行）。
`Settle`（清算値）・`IV`・`OI`・`Vo`・`Strike`・`dte`・`UnderPx`・`PCDiv` を使う。

**bid/ask が無く清算値のみ**なので、**合格しても判定は `PAPER ONLY`**（この枠の既定ルール）。
実弾化には実板・複数レッグ同時約定の検証が別途必要。

## 2. 建て方（確定）

- 各週の**最初の営業日**に1組だけ建てる（重複建玉なし）
- ストライクは **ATM**（その日の `UnderPx` に最も近い）。put/call は **call** に固定
- 期近レッグ: `dte` が **[7, 25]** の最も近い限月 → **売り**
- 期先レッグ: 同一ストライクで `dte` が **[35, 80]** の最も近い限月 → **買い**
- 両レッグとも `Vo > 0` かつ `OI ≥ 100`
- **保有5営業日**、その日の清算値で手仕舞い

## 3. シグナル（確定）

期間構造の傾き `slope = IV_near − IV_far` を、過去252営業日の z で標準化する。

- **z ≥ +0.5 のときだけ建てる**（期近が普段より割高＝売る価値がある）
- z < +0.5 は見送り。**逆方向（期先を売る）は建てない**

閾値 +0.5 は既存2本（IV−RV, skew）と同じ水準を流用し、最適化しない。

## 4. 損益とコスト

- 損益は **ネットデビットに対する比率**で測る（`(exit_value − entry_debit) / entry_debit`）
- コストは**両レッグ往復で 4ティック相当**を控除（清算値ベースなので保守側の固定控除）
- 建玉サイズは1組固定。資金効率・レバは本試行では評価しない

## 5. 判定（実測を見る前に確定）

主仕様が次を**すべて**満たしたときのみ `PAPER ONLY` として次段階へ:

1. 取引数 **≥ 30**
2. **グロス Sharpe ≥ 1.0**（取引単位・年率換算）
3. **最大利益取引の利益シェア < 20%**
4. **最悪取引 > −100%**（デビット以上に損失が出ていない＝定義済みリスクが実際に効いている）
5. 年別（2019-2026）で**負の年が3年以下**

## 6. 感度分析（主仕様への昇格禁止）

z 閾値 0.0 / +1.0、保有 3 / 10営業日、put 版。**良かったセルを主仕様にしない。**
