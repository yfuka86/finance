作成: 2026-08-08（**フォワード期間のリターンを一切見ていない時点で確定**）
ファミリー: `CORPORATE_EVENTS` / 状態: **SEALED → 2027-12-01**

## 0. 位置づけ

V4（フロア¥1億）は OOS24+ で中央値+4.61%・増分単独+4.12%と頑健だったが、
利益集中 25.96%（基準<20%）の1点で NO-GO。集中は標本量で薄まる性質のため、
**新しい未使用期間のイベント供給で1回だけ再判定する**。仕様変更は一切ない
（V5禁止の事前登録に抵触しない: 母集団・シグナル・モデルは V4 凍結仕様のまま、
判定期間だけが新しい）。

## 1. 凍結仕様（V4と同一・変更禁止）

- イベント: 同一期内の予想配当+20%以上（PIT・DiscDate順）
- 適格: PBR∈(0,1]（生値終値×当時BPS）・EPS>0・OP>0・前日売買代金≥**¥1億**
- エントリ: 開示翌営業日寄成 / エグジット: 60営業日後引け / 同時最大10案件
- モデル: Ridge(α=10)+impute+standardize・FEATURES 7本・**学習 exit<2024-01-01 固定**
  （フォワード期間中の再学習・再選択は行わない）
- コスト: 往復40bps

## 2. データ体制（本書と同時に構築）

- `scripts/collect_fins_incremental.py` — fins/summary を日次増分収集
  （静的スナップショットは2026-04-24で停止していた）
- `scripts/collect_v4_forward_events.py` — 凍結仕様の適格イベントを
  `data/value_event_v4_forward/events.jsonl` に**追記のみ**（リターン計算なし。
  凍結モデルの予測値=発生時点で運用者が知り得る値のみ記録）
- launchd `jp.finance.v4-forward` が毎営業日 19:30 に 日次バー→fins→台帳 を単独実行

## 3. 判定（実測を見る前に確定）

- 対象イベント: **2026-05-01〜2027-08-31**（開示日基準）
- 判定日: **2027-12-01以降に1回だけ** `scripts/verify_v4_forward.py`
  （日付ガード・上書き不能 verdict.json・オーバーライドフラグなし）
- 基準: ①採用案件 ≥30 ②40bps後の案件中央値 >0 ③最大案件利益シェア <20%
- 副記（判定に使わない）: 封印時点より後に発生した純フォワード部分単独の同統計
- 供給不足で①を満たさない場合も **NO_GO**（標本供給の壁の再確認として受け入れる）

## 4. 開示事項

- 2026-05-01〜2026-08-07 の約3ヶ月分は封印構築時のキャッチアップ（`backfilled: true`）。
  この期間の結果はディスクに存在するが、**どのスクリプトも読んでいない**
  （台帳はリターンを計算しない設計）。純フォワード部分の副記で依存を可視化する。
- OOS 2024-01〜2026-04 は V4 判定で消費済み。本書の判定窓とは重複しない。

## 5. 禁止事項
